# Дневник питания — контекст проекта

Закрытое приложение для учениц программы снижения веса и коррекции пищевого поведения (заказчица — автор
марафонов и индивидуального сопровождения) и веб-кабинет наставника. Исходное ТЗ и план — `docs/PLAN.md`.
Весь интерфейс и тексты — на русском, к ученице обращаемся на «вы», бережно, без оценок и стыда.

## Где что лежит

- `apps/api` — сервер: Fastify + tRPC, PostgreSQL (Drizzle), фоновые задачи (`src/worker.ts`, `src/jobs.ts`), скрипты в `src/scripts`.
- `apps/student` — PWA ученицы (React, Vite, vite-plugin-pwa), обработчик push — `public/push-handler.js`.
- `apps/admin` — кабинет наставника (React, Vite).
- `packages/shared` — формулы целей (`nutrition.ts`), статистика дня/недели (`stats.ts`), даты с часовыми поясами,
  сопоставление продуктов, протокол тревожных сигналов (`safety.ts`). Zod-схемы — отдельная точка входа
  `@hud/shared/schemas` (чтобы zod не попадал в сборку приложений).
- `packages/db` — схема, миграции (`drizzle-kit generate`), база продуктов и справочники (`src/seed`).
- `packages/ai` — локальный разбор еды, шаблонные тексты, адаптеры GigaChat/YandexGPT, проверка ответов модели.
- `packages/ui` — общие компоненты; графики — отдельно `@hud/ui/charts` (recharts грузится лениво).

## Команды

```
pnpm install
pnpm dev            # сервер :3000, ученица :5173, кабинет :5174
pnpm typecheck
pnpm test           # нужна PostgreSQL (postgres:postgres@localhost:5432), база hud_test пересоздаётся
pnpm db:generate    # новая миграция после изменения packages/db/src/schema.ts
pnpm db:migrate && pnpm db:seed
pnpm create-admin --phone "+7…" --name "Имя"
pnpm --filter @hud/api worker | vapid-keys | reset-totp | setup-webhooks
```

Локальная настройка с нуля — `docs/LOCAL_SETUP.md`. Развёртывание — `docs/DEPLOY.md`.

## Ключевые решения

- PWA вместо магазинов приложений; хостинг и данные — в РФ (152-ФЗ); ИИ по умолчанию российский.
- Калории и БЖУ считает код по базе продуктов; ИИ только разбирает текст. Цифры в итогах и отчётах тоже
  считает код, ИИ пишет лишь текст, и этот текст проверяется (`packages/ai/src/guardrails.ts`).
  Если модель недоступна или ответ не прошёл проверку — правила и шаблоны.
- Вход по одноразовому коду на телефон; у наставников — ещё TOTP (обязателен в продакшене).
- Уведомления: лента в приложении + Web Push + боты Telegram/MAX (`apps/api/src/services/delivery.ts`);
  на экране блокировки — без личного содержимого.
- Живые обновления: SSE `/api/events` + PostgreSQL LISTEN/NOTIFY.
- Решения, принятые без заказчицы, и где их менять — `docs/OPEN_QUESTIONS.md`. Новые такие решения
  записывать туда же.

## Подводные камни (уже наступали)

- После входа нужно `queryClient.clear()`, иначе в кэше остаётся «не авторизован» и экран входа зацикливается.
- В тестах очищать данные через `DELETE`, не `TRUNCATE … CASCADE` — каскад по `foods.created_by_id` стирает базу продуктов.
- Время создания записей брать из `deps.now()`, а не `defaultNow()` БД — иначе тесты с фиктивными часами ломаются.
- Ссылки на продукты, которых уже нет в базе, при сохранении приёма пищи обнуляются (`dropUnknownFoods`).
- Внутренние ошибки сервера не показываются пользователю (`errorFormatter` в `apps/api/src/trpc.ts`).

## Состояние и что дальше

Готова основа MVP + push, боты, 2FA, протокол тревожных сигналов, живые обновления (78 тестов).
Не проверено на реальных ключах: GigaChat/YandexGPT, боты Telegram/MAX (формат ссылки запуска MAX).
Ждут заказчицу и специалиста: формулы, база продуктов, тексты согласий, протокол тревожных сигналов, выбор мессенджера.

Предложенные следующие шаги: подготовка к пилоту (стенд в российском облаке, браузерные тесты в CI, мониторинг
и бэкапы, форма отзыва и метрики пилота), затем этап 2 (фото, голос, чат, PDF, шаблоны комментариев, CRM)
и идеи сверх ТЗ (шкала голода/сытости, замеры тела). Серии дней и рейтинги сознательно не предлагаем —
для аудитории с трудностями в пищевом поведении они добавляют давления.
