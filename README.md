# Дневник питания

Закрытое приложение для учениц программы снижения веса и коррекции пищевого поведения:
дневник веса, питания и эмоций с ИИ-расчётом калорий, итогами дня и недельными отчётами,
а также веб-кабинет наставника.

- План и архитектура: [`docs/PLAN.md`](docs/PLAN.md)
- Открытые вопросы и решения по умолчанию: [`docs/OPEN_QUESTIONS.md`](docs/OPEN_QUESTIONS.md)
- Развёртывание: [`docs/DEPLOY.md`](docs/DEPLOY.md)

## Структура

```
apps/
  student/   приложение ученицы — PWA (React, Vite), ставится на экран «Домой»
  admin/     кабинет наставника (React, Vite)
  api/       сервер (Fastify + tRPC), фоновые задачи (worker), скрипты
packages/
  shared/    формулы расчётов, статистика дня и недели, даты, схемы валидации
  db/        схема PostgreSQL (Drizzle), миграции, база продуктов и справочники
  ai/        разбор еды и тексты итогов: локальный движок, GigaChat, YandexGPT, проверки ответов
  ui/        общие компоненты интерфейса и графики
infra/       конфигурация Caddy
```

## Быстрый старт (разработка)

Нужны Node.js 22+, pnpm 10+ и PostgreSQL 16+.

```bash
pnpm install
cp .env.example .env                       # DEV_OTP_CODE=111111 — код входа без SMS
createdb hud                               # или через psql: CREATE DATABASE hud;
pnpm db:migrate && pnpm db:seed            # схема, справочники, база продуктов
pnpm create-admin --phone "+79990000000" --name "Анна"
pnpm dev                                   # сервер :3000, ученица :5173, кабинет :5174
pnpm --filter @hud/api worker              # фоновые задачи (по желанию)
pnpm --filter @hud/api vapid-keys          # ключи для push-уведомлений (по желанию, в .env)
```

1. Откройте кабинет http://localhost:5174 и войдите по телефону администратора (код `111111`).
2. Добавьте ученицу — кабинет выдаст ссылку-приглашение.
3. Откройте ссылку (лучше в мобильном режиме браузера) и войдите по телефону ученицы.

## Проверки

```bash
pnpm typecheck     # TypeScript во всех пакетах
pnpm test          # модульные и интеграционные тесты (нужна PostgreSQL; база hud_test пересоздаётся)
```

Тестам сервера нужна PostgreSQL по адресу `postgres://postgres:postgres@localhost:5432` — или задайте
`TEST_DATABASE_URL`. Те же проверки и сборка приложений запускаются в GitHub Actions (`.github/workflows/ci.yml`).

## Состояние разработки

**Готово (основа MVP):**

- вход по приглашению и одноразовому коду на телефон, роли (администратор, наставник, ученица),
  закрепление учениц за наставником;
- согласия (обязательные и по желанию) с версиями текстов;
- стартовая анкета, расчёт ИМТ, обмена, калорийности и БЖУ с правилами безопасности; ручные цели наставника;
- дневник: вес с графиком; приёмы пищи с разбором текста (правила + база продуктов, адаптеры GigaChat/YandexGPT),
  правкой граммов, заменой продуктов, повтором прошлых приёмов; отметка переедания с ситуациями и эмоциями;
- итоги дня и недельные отчёты: цифры считает код, текст пишет ИИ или шаблон, ответы ИИ проверяются
  на выдуманные эмоции, оценочные слова и неизвестные числа;
- комментарии наставника к приёмам пищи, дням и неделям, ответы ученицы, лента уведомлений;
- кабинет: «Требуют внимания», список учениц с фильтрами, карточка (обзор, дневник, отчёты, эмоции, цели,
  доступ, общение, профиль), программы и потоки, справочники и база продуктов;
- сроки доступа: продление, пауза, закрытие, история; автоматическое завершение и предупреждения;
- напоминания о взвешивании и дневнике по местному времени, недельные отчёты по расписанию;
- выгрузка своих данных ученицей, журнал просмотров данных наставником, учёт запросов к ИИ;
- PWA-манифест и иконки, Docker-образы, docker compose, Caddy, CI;
- уведомления на телефон (Web Push) и боты Telegram/MAX: привязка по ссылке, доставка с учётом настроек,
  повтор при сбое, на экране блокировки — без личного содержимого;
- двухфакторная защита кабинета (TOTP, QR-код), обязательная в продакшене;
- протокол тревожных сигналов (черновик): бережное сообщение ученице, срочный сигнал наставнику;
- живые обновления кабинета и приложения (SSE + PostgreSQL LISTEN/NOTIFY).

**Следующие шаги:** проверка адаптеров ИИ и ботов на реальных ключах, утверждение протокола тревожных сигналов
и базы продуктов специалистом, затем этап 2 (фото, голос, CRM и рассылки, экспорт в PDF).
